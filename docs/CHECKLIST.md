# Чек-лист против критериев жюри — что учтено и что ещё можно

Критерии (слайд 11 брифа): метрики на скрытом наборе **45 %**, инженерная часть **30 %**, удобство интерфейса **15 %**,
презентация **10 %**. Правила: Docker, автономная работа без сети, ≤ 5 мин на 1000 записей, старт контейнера ≤ 3 мин,
данные не выносятся, словари и справочники приветствуются; **запрещено** сопоставление по id записи и возврат готового
ответа по точному совпадению всей строки.

## 0. Правила — где мы

| правило | у нас | доказательство |
|---|---|---|
| Docker, всё внутри образа | образ `python:3.11-slim` + правила + ONNX 10,5 МБ + gazetteer.sqlite 36 МБ | `make offline-check` запускает образ с `--network none` |
| старт ≤ 3 мин | **1 с** до `healthy` | `scripts/offline_check.sh` |
| ≤ 5 мин на 1000 записей | **0,66 с** на 1000, 83 МиБ памяти | там же |
| данные не выносятся | `train.json` в `.gitignore`; Claude как второй разметчик только с разрешения (`make day0-claude`) | `docs/ML.md` §5 |
| никаких «ответов по id / по точной строке» | ответ строится из токенов строки правилами и моделью; нигде нет таблицы «строка → ответ»; 15 из 17 искажений строки не меняют ответ | `make robustness`, `api/tests/test_robustness.py` |

## 1. Метрики на скрытом наборе (45 %)

**Учтено**

* Точная копия метрики жюри (`eval/metric.py`, строгий режим — пессимистичнее, чем обещает бриф). Все цифры ниже — ею.
* Гибрид: грамматика (ключевые слова RU/KK/Latin) ⊕ char-CNN+BiLSTM+CRF ⊕ арбитр с порогами, подобранными по метрике.
  Гибрид лучше и правил, и модели по отдельности на каждом наборе.
* Независимые наборы, которые писали не мы (Claude Opus 5.5, 22 темы): №1 526 строк — 97,08 → 99,47;
  **№2 263 строки, нетронутый, замерен один раз: 96,30 → 99,33**; №3 263 строки: 93,91 (main) → 98,36 (PR #3) →
  99,78 после исправлений; **«злой» набор №4 (217 строк, 16 тем того, что ломает парсеры): 85,69 → 91,66 → 98,92**;
  **«злой» набор №5, нетронутый, замерен один раз после всего: 83,51 (main) → 90,42 (PR #3) → 96,47**
  ([BENCHMARK.md](BENCHMARK.md)). Плюс стресс-набор (106), сёла (40), робастность (17 искажений), фаззинг (2 500 строк).
* Соглашения о разметке зафиксированы (16 решений, [CONVENTIONS.md](CONVENTIONS.md)); каждое спорное — переключатель в
  `conventions.yaml`.
* Неправильная раскладка клавиатуры («Fkvfns? ek/ F,fz 10» = «Алматы, ул. Абая 10») и латинские буквы-двойники («Aлмaты»)
  распознаются: 21 метаморфическое искажение в `make robustness`, 90–99 % ответов не меняются.
* Калиброванная уверенность (ECE 0,019 на независимом наборе) → очередь на ручную проверку.
* День 0: `make day0` — `train.json` → разметка двумя независимыми способами → согласие = эталон, спор = проверка →
  дообучение → пороги → калибровка → A/B. Это главный рычаг: скрытый набор — те же данные Jana Post, что и `train.json`.

**Что ещё можно (по ожидаемому выигрышу)**

1. **`train.json` в первый час.** Прогнать `make day0 --limit 300 --skip-train`, глазами прочитать 200 строк и очередь
   споров: 10 самых частых паттернов реальных данных стоят больше любой синтетики. Потом полный `make day0`.
2. **Ответы организаторов на Q4 (область Абай / Абайская область), Q6 (ЖК с типом или без), Q7 (корпус → 12/2),
   Q13 (офис = квартира?).** Каждый — переключатель, каждый может стоить 0,3–1 балла на скрытом наборе.
3. **Дообучение на реальных строках (v7+):** warm start с v6, реальные строки ×5 + 60k синтетики — это уже в `day0`.
   На 789 строках Claude (v7) это уже пробовали: +0,2 на «злом» наборе, −0,5 на dev — мало данных, переобучение; нужно
   5–10 тыс. строк (п. 4).
4. **Claude как учитель:** 5–10 тыс. реалистичных размеченных строк (≈ 30 мин, копейки) в обучение вместо части синтетики.
   Генератор есть (`eval/llm_generate.py`), валидаторы есть.
5. **Транслит в признаках модели:** gazetteer-множества для CRF сейчас кириллические; добавить транслит-ключи — латиница
   будет узнаваться и моделью, не только правилами.
6. **Индексы Казпочты:** 6-значный индекс в начале строки сейчас игнорируется; таблица индекс → область/город (открытые
   данные) заполнит город там, где его нет в строке (не штрафуется метрикой, но даёт справочные поля).
7. **Активное обучение между прогонами:** 10 % самых неуверенных → UI → corrections.jsonl → `make day0` снова (3 цикла).
8. **Ансамбль / модель побольше:** hidden 256 и/или второй тагер с другим seed + голосование. Запас по скорости ×100.

## 2. Инженерная часть (30 %): справочные поля, сбор справочника, архитектура, код

**Учтено**

* Справочник из OpenStreetMap (`data_pipeline/build_gazetteer.py`, ~90 с): 5,4 тыс. населённых пунктов ru/kk, 20 областей,
  районы городов, 5,3 тыс. микрорайонов/ЖК, 50 тыс. улиц, **977 тыс. домов с координатами**. Только ODbL-данные в репозитории.
* Справочные поля заполняются из него, **никогда не переписывая написанное**; у каждого поля — происхождение
  (`string` / `string+table` / `gazetteer:osm` / `gazetteer:seed`).
* Геокодирование до дома (96 % реальных адресов, набранных «как клиенты»), лестница точности, подсказки при вводе
  (`/api/v1/suggest`) — то, что делают Яндекс и 2ГИС, но офлайн.
* Архитектура описана (ARCHITECTURE.md, ML.md), explain-режим отдаёт спаны и решения арбитра, 227 автотестов, история
  экспериментов с хэшами артефактов (EXPERIMENTS.md), воспроизводимые `make`-цели для каждого шага.
* Ни одна запись не теряется: ошибка в строке → пустой ответ с уверенностью ≤ 0,08, пакет идёт дальше.

**Что ещё можно**

1. Таблица индексов Казпочты и КАТО-коды населённых пунктов в справочник (официальные идентификаторы в ответе).
2. Офлайн-карта в UI: точка геокодирования на упрощённой карте Казахстана (GeoJSON областей в образе, без тайлов).
3. `uvicorn --workers 2–4` и batch-инференс ONNX — на случай, если жюри подаст 100 тыс. строк.
4. Линтер + типы в CI (ruff, mypy), покрытие тестами в бейдже; один `make check` = тесты + робастность + офлайн-проверка.
5. Версионирование артефактов в `/version` уже есть; добавить `GET /metrics` (Prometheus) для «продакшн-вида».

## 3. Удобство интерфейса (15 %) — трек Yasmin

Учтено: загрузка файла/JSON, таблица, подсветка спанов, правка, горячие клавиши, очередь на проверку, экспорт исправлений,
подсказки при вводе. Можно: карта (см. выше), массовое принятие по порогу уверенности, фильтр «только расхождения
с Claude», тёмная тема, клавиатурная навигация по очереди.

## 4. Презентация (10 %)

Учтено: 12 слайдов на русском (задача → архитектура → данные → цифры → независимая проверка → робастность → гео →
уверенность → день 0 → продакшн → вопросы). Можно: 7-минутный сценарий с таймингом, живая демонстрация на 5 строках из
стресс-набора, запасное видео демо на случай проблем с ноутбуком, один слайд «что мы НЕ делаем» (нет таблицы ответов,
нет внешних API).
